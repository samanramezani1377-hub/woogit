# WooGit — Connection & Sync Strategy

## اصل اتصال نسخه اول

برای سه محور اصلی محصول، کاربر باید بتواند با حداقل اصطکاک و فقط با:

- آدرس فروشگاه
- WooCommerce Consumer Key
- WooCommerce Consumer Secret

اتصال را برقرار کند.

کاربر نباید برای استفاده‌ی محوری مجبور به نصب سرویس اضافه، ساخت حساب جداگانه یا طی کردن Setup پیچیده باشد.

## Data Version / Commit Number (تصمیم نهایی)

طبق تصمیم قطعی ثبت‌شده در `docs/DECISION_TRACKER.md` (پرسش ۰۱)، مکانیزم نسخه‌ی V1 مشخص شده است:

- **نسخه اول:** تشخیص نسخه/آخرین تغییر هر Entity با استفاده از `date_modified_gmt` ووکامرس انجام می‌شود. این مقدار «نسخه تشخیصی سمت فروشگاه» است، نه یک شناسه Commit واقعی و یکتای تاریخچه تغییرات؛ اما برای نیاز V1 کافی و بدون وابستگی به افزونه یا بک‌اند اضافی است.
- **آینده:** یک افزونه‌ی همراه سبک برای WordPress/WooCommerce می‌تواند یک counter سراسری دقیق‌تر نگه دارد و endpoint اختصاصی مانند `GET /wp-json/woogit/v1/version` ارائه دهد. این مسیر به نسخه‌های بعدی موکول شده و پیش‌نیاز V1 نیست.
- این لایه باید طوری طراحی شود که در آینده بتوان `date_modified_gmt` را بدون بازطراحی Core با شناسه Commit واقعی (از طریق افزونه) جایگزین یا تکمیل کرد.

## Optional Enhancements

قابلیت‌های غیرمحوری مثل Setup Wizard پیشرفته، تست‌های تشخیصی، تنظیمات پیشرفته Sync و ابزارهای مدیریتی اضافی می‌توانند در مسیر Optional قرار گیرند و نباید مسیر استفاده از سه محور اصلی را کند کنند.

## اصل Performance

هیچ قابلیت معماری یا Setup اختیاری نباید باعث شود:

- زمان Launch اپ افزایش محسوس پیدا کند.
- مسیر مشاهده سفارش کند شود.
- افزودن/ویرایش محصول پیچیده شود.
- برای هر باز شدن اپ درخواست‌های غیرضروری شبکه انجام شود.

Core باید Local-first باشد و بررسی نسخه/Sync تا حد ممکن سبک، lazy و پس‌زمینه‌ای باشد.
