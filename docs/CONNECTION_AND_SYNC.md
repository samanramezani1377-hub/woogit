# WooGit — Connection & Sync Strategy

## اصل اتصال نسخه اول

برای سه محور اصلی محصول، کاربر باید بتواند با حداقل اصطکاک و فقط با:

- آدرس فروشگاه
- WooCommerce Consumer Key
- WooCommerce Consumer Secret

اتصال را برقرار کند.

کاربر نباید برای استفاده‌ی محوری مجبور به نصب سرویس اضافه، ساخت حساب جداگانه یا طی کردن Setup پیچیده باشد.

## Data Version / Commit Number

برای داشتن «شماره کامیت» واقعی و سراسری، خود اپ به‌تنهایی کافی نیست؛ باید یک **Source of Truth سمت فروشگاه** وجود داشته باشد.

### مسیر پیشنهادی

یک افزونه‌ی همراه سبک برای WordPress/WooCommerce یک counter سراسری نگه می‌دارد و endpoint اختصاصی مانند:

`GET /wp-json/woogit/v1/version`

ارائه می‌کند.

این endpoint باید با همان مکانیزم اعتبارسنجی اتصال موجود قابل استفاده باشد تا کاربر برای قابلیت Commit/Version مجبور به وارد کردن credential دیگری نباشد.

### نکته مهم

«شماره کامیت» برای کارکرد دقیق و قابل اعتماد، **به چیزی فراتر از سه credential در سمت کاربر نیاز ندارد**؛ اما در سمت فروشگاه به یک مکانیزم کوچک برای نگهداری و افزایش counter نیاز دارد.

بنابراین گزینه‌ها:

1. **پیشنهادی:** افزونه‌ی WooGit روی WordPress → counter دقیق + endpoint سبک.
2. **Fallback:** بدون افزونه، استفاده از `date_modified_gmt` به‌عنوان نسخه تقریبی؛ دقت و رفتار آن محدودتر است.

## Optional Enhancements

قابلیت‌های غیرمحوری مثل Setup Wizard پیشرفته، تست‌های تشخیصی، تنظیمات پیشرفته Sync و ابزارهای مدیریتی اضافی می‌توانند در مسیر Optional قرار گیرند و نباید مسیر استفاده از سه محور اصلی را کند کنند.

## اصل Performance

هیچ قابلیت معماری یا Setup اختیاری نباید باعث شود:

- زمان Launch اپ افزایش محسوس پیدا کند.
- مسیر مشاهده سفارش کند شود.
- افزودن/ویرایش محصول پیچیده شود.
- برای هر باز شدن اپ درخواست‌های غیرضروری شبکه انجام شود.

Core باید Local-first باشد و بررسی نسخه/Sync تا حد ممکن سبک، lazy و پس‌زمینه‌ای باشد.
