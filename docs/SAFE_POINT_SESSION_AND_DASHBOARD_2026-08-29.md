## Session Persistence — رفتار قطعی

### بعد از اتصال موفق فروشگاه
- شناسه فروشگاه فعال در session محلی نگهداری می‌شود.
- credentialهای حساس در SharedPreferences یا فایل متنی ذخیره نمی‌شوند.
- credentialها از Secure Credential Store استفاده می‌کنند.

### بعد از بستن یا restart برنامه
- فروشگاه قبلی باید از session محلی بازیابی شود.
- اگر active store id موجود نباشد، فروشگاه متصل موجود در local data می‌تواند برای restore استفاده شود.
- بستن یا خروج عادی از برنامه نباید باعث درخواست دوباره Consumer Key، Consumer Secret، آدرس فروشگاه یا اطلاعات اتصال شود.

### Disconnect
- Disconnect با بستن برنامه متفاوت است.
- در Disconnect، session فروشگاه پاک می‌شود و اتصال مجدد در اجرای بعدی مورد انتظار است.

## Dashboard Sales — رفتار قطعی

فروش داشبورد از سفارش‌های واقعی دریافت‌شده از WooCommerce محاسبه می‌شود تا مقدار ناقص/صفر گزارش summary باعث نمایش فروش اشتباه نشود.

- `CANCELLED` و `FAILED` در فروش خالص لحاظ نمی‌شوند.
- وضعیت‌های معتبر مانند `COMPLETED` لحاظ می‌شوند.
- تنظیمات ارز از WooCommerce گرفته می‌شود.
- HTML موجود در currency symbol نباید مستقیماً داخل متن عددی UI نمایش داده شود.

## Incident / lessons learned

یک پیاده‌سازی اولیه به API اشتباه local store متکی شد و CI به‌دلیل referenceهای نامعتبر fail شد. نسخه Safe Point با استفاده از API واقعی `SqlStoreDataSource` اصلاح شده و CI آن موفق است.

در تغییرات بعدی:

- API کلاس‌های local data source نباید حدس زده شود.
- قبل از تغییر persistence، implementation واقعی کلاس و مسیر credential بررسی شود.
- رفع CI نباید با حذف یا ساده‌سازی خطرناک منطق موجود انجام شود.
- تغییرات باید محدود به دامنه درخواست باشند و diff بررسی شود.
